# 基本概念与核心公式（可编程化）

1. 颜色空间建议
   * **RGB**：适合显示/像素级操作，但不是感知上均匀（亮度/饱和度变化的感知不是线性的）。
   * **HSL / HSV**（从 RGB 转换）更利于配色逻辑（按色相/饱和度/明度来操作）。实际推荐：配色算法在 HSL/HCL/Lab 空间做变换，最后再转回 RGB/HEX 显示。
2. 常用转换（伪公式）
   * RGB → HSL：用标准库（如 Python 的 `colorsys.rgb_to_hls`）或已知公式。
   * HSL → RGB：`colorsys.hls_to_rgb`。
   * **感知互补色（推荐）**：`new_hue = (hue + 180) % 360`（在 HSL 空间加 180°）然后保持或微调 S、L。
   * **像素反色（不等同互补）**：`invert_rgb = (255-R, 255-G, 255-B)` —— 这是图像反转/负片，不一定视觉上是“互补”。

# 常见配色规则（可直接编码）

1. 色轮关系（色相角度）
   * **近邻色（Analogous）**：色相差约 **±15–45°**（常用 ±30°）。适合柔和过渡。
   * **互补色（Complementary）**：色相约 **+180°**，高对比，常用于强调/点缀。
   * **三角配色（Triadic）**：每隔 **120°**，对比但均衡（活泼）。
   * **四方配色（Tetradic / 双互补）**：两对互补色，适合复杂调色但易乱，需控制饱和度/明度。
   * **分裂互补（Split-complementary）**：互补色两侧各偏 ±20–40°，张力小于纯互补。
2. 配色比例（设计常用）
   * **60 / 30 / 10 规则**（最常见）：主色 60%（大面积），次色 30%，强调色 10%。
   * 另常见：**70 / 25 / 5**（更保守），或 **80 / 15 / 5**（极简）。
   * 编程上可把 canvas/background 设为主色低饱和、文字/控件用次色/强调色。
3. 饱和度与明度（可量化区间）
   * **背景色**：S = **0–30%**（或低饱和），L = **85–98%（浅）** 或 **5–20%（深）**。
   * **主色（大面积）**：S = **20–60%**，L = **40–70%**（避免纯 100% 饱和大面积）。
   * **强调色 / 按钮 / icon**：S = **50–100%**，L = **35–65%**（高饱和用于小面积更醒目）。
   * **文本**：通常 S 不重要，关键是 L 与背景对比（见对比比率）。
4. 对比与可读性（必须量化）
   * 遵循 WCAG 指南：**正文文本对比度 ≥ 4.5:1**（大字 ≥ 3:1）；**增强级 ≥ 7:1**。
   * 对比比率可以通过将 RGB 转为相对亮度再计算得出（标准公式，可用现成库）。

# 冲色（Vibrating / Clash）与如何避免

1. 为什么“冲色”出现：两色色相相差很大且**明度相近**、**都高饱和**时，边缘会“振动”或视觉不稳定。
2. 避免方法（可程序化）：
   * 若两色色相差 > 90° 且 |L1 - L2| < 10% 且 S1,S2 > 60% → **自动降低其中一个的 S（减 20–40%）或调整 L（+/-15%）**。
   * 在并列强对比色之间加入一个中性缓冲（灰/米色）作为分隔。
   * 使用分裂互补或三角而非纯互补来降低冲突感。

# 可直接用的“工程化”建议（步骤形式）

1. 取屏幕色（RGB）→ 转 HSL。
2. 选择主色（主 hue, S_base, L_base）。
3. 生成候选配色：Analogous（±30°）、Complement（+180°）、Triadic（±120°）、Split（comp ±30°）。
4. 根据用途套用数值范畴（上面“饱和度与明度”）。
5. 计算对比度（文本/背景），若不满足 WCAG 则调整 L（提升或降低）直到满足。
6. 检查“冲色规则”：若触发则自动弱化饱和度或在两色间插入中性色。

# 具体示例（可直接拿来用）

以基色 `RGB = (46, 120, 246)`（HEX `#2E78F6`）为例，在 HSL 空间（约）为 `H=218°, S=92%, L=57%`。基于它的常见方案（用程序按 H±/H+180° 计算）：

* 主色（Base）: `#2E78F6` — RGB (46,120,246) — HSL ≈ (217.8°, 91.7%, 57.3%)
* 近邻色1（Analog -30°）: `#2EDCF6` — RGB (46,220,246) — HSL ≈ (187.8°, 91.7%, 57.3%)
* 近邻色2（Analog +30°）: `#482EF6` — RGB (72,46,246) — HSL ≈ (247.8°, 91.7%, 57.3%)
* 互补色（+180°）: `#F6AC2E` — RGB (246,172,46) — HSL ≈ (37.8°, 91.7%, 57.3%)
* 分裂互补: `#F6482E` / `#DCF62E`（2 个偏向互补旁的颜色）
* 三角配色（±120°）: `#F62E78` / `#78F62E`

把它们套 60/30/10：

* 主色（60%）：`#2E78F6`（用于 logo、大标题、重要图形）
* 次色（30%）：`#2EDCF6`（用于卡片背景、次级按钮）
* 强调色（10%）：`#F6AC2E`（用于 CTA、警示、强调）

> 注：上面互补由 HSL 计算得到的颜色（肉眼更和谐）。如果直接做像素反色 `255-R` 会得到不同结果（视觉上通常不如 HSL 互补）。

# 编程上实用的小函数/伪码（思路）

* 互补色：`h2 = (h + 180) % 360; (r2,g2,b2) = HSLtoRGB(h2, s, l)`

* 生成 analog：`h +/- 15~45`（可随机或固定30）

* 自动修正冲突：

  ```
  if abs(L1-L2)<10 and S1>60 and S2>60 and hue_diff>90:
      reduce S of one color by 25%
  ```

* 对比度检查：使用 WCAG 对比公式（可用现成函数库）。

# 进阶建议（更佳感知一致性）

* 用 **CAM02-UCS / Lab / HCL** 空间做色差计算和插值（比 HSL 更符合人眼感知），尤其是要做渐变或调和色阶时。
* 对于印刷或品牌用色，校验具体显示器/打印机的色域（sRGB vs AdobeRGB）。
